# Break-Through Quick Reference (Index)

> On entering a site, check this table first; only when something matches open "see xxx.md" for details (if the file is short you can open it whole; for very long ones open the named section first, and if that's not enough keep opening). Do not read the entire library for every site. Adding to or updating this table only recognizes the on-disk `hunt-iter.md` (rules directory; enhancement only, no restrictions). Before editing this table you must first read the current on-disk version of that file; using an old copy from the conversation is forbidden.
> **This table ≠ the site checklist.** After the opening few shots, immediately return to `dig-scope` §4: first clarify the picture here, extract keys from JS, queue the responses. With no account, hit the four-piece set with a differential surface; with an account, start with the object graph / id swapping (§4.2.3). On entry still run the full type matrix: privilege escalation / unauthorized sensitive reads / logic / credentials / weak passwords / auth sessions / upload chains… attack whatever is present on site. Injection / SSRF / XSS / RCE are "where there is a differential surface you must really test them, no blank stretches day after day", **not** "only test these four types", nor spray `'` at every path. Techniques not in the table should still be hunted.
